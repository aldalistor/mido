# تحليل ERP_LOGIN.frm

## النتيجة العامة

الملف المرفق ليس ملفًا نصيًا قابلًا للتحرير مباشرة، بل ملف Oracle Forms ثنائي. تم استخراج النصوص الوصفية منه دون تشغيله. يظهر أن الشاشة ليست مجرد نموذج اسم مستخدم وكلمة مرور؛ بل تهيئ جلسة النظام كاملة قبل فتح القائمة الرئيسية.

## العناصر المستخلصة

| العنصر في النموذج القديم | الدلالة في المشروع الجديد |
|---|---|
| `ERP_LOGIN` و`LOGIN` | شاشة الدخول الأساسية |
| `USER_NO` و`FORM_NO` | هوية المستخدم ورقم النموذج/الشاشة |
| `CMP_NO` و`BRN_NO` و`BRN_YEAR` | اختيار الشركة والفرع والسنة المالية |
| `LANG_NO` و`Lang_Dir` و`RIGHT_TO_LEFT` | دعم اللغة العربية والإنجليزية واتجاه الواجهة |
| `IAS_USR_PKG` و`GET_USR_NM` | جلب بيانات المستخدم والتحقق من الحساب |
| `CHK_USR_FRM_PRV` و`GET_USR_APPRV` | فحص صلاحية الوصول والموافقات |
| `IAS_USR_LGN_HSTRY` | سجل الدخول والخروج ومحاولات الدخول |
| `S_BRN` | بيانات الفروع والشركة والصورة/الهوية |
| `LOAD_PARAMETERS` و`IAS_PARA_*` | تحميل إعدادات النظام والمخزون والمبيعات والمشتريات والضرائب |
| `IAS_GEN_PKG.GET_SYSDATE` و`GET_CURDATE` | تاريخ النظام والتاريخ المحاسبي |
| رسائل `Field Cannot Be Null` و`Invalid Data` | قواعد تحقق ورسائل أخطاء عربية/إنجليزية |
| `ALTER USER ... ACCOUNT UNLOCK` | معالجة حسابات Oracle القديمة؛ لا ينبغي تنفيذها تلقائيًا من تطبيق المستخدم الجديد |

## ملاحظة مهمة حول التاريخ

الملف يحتوي على مفاهيم `BRN_YEAR` و`GET_SYSDATE` و`GET_CURDATE`، كما أن النظام القديم يعتمد على إعدادات تاريخ للفترات المحاسبية. لذلك لا يُنصح بتجاوز التاريخ مباشرة، لأن ذلك قد يسبب قيودًا غير متوازنة أو ترحيلًا داخل فترة مغلقة. التصميم الجديد يستخدم تاريخ عمل للشركة، وتاريخ إقفال، وحدًا اختياريًا للترحيل بأثر رجعي، مع صلاحية مستقلة باسم `BACKDATE_POSTING` وتسجيل كل عملية في سجل التدقيق.

## قرار التحويل

لن يتم تحويل ملف `.frm` إلى تطبيق جديد سطرًا بسطر؛ الأفضل إعادة بناء شاشة الدخول والمنطق المحاسبي على طبقة حديثة، مع الحفاظ على أسماء المفاهيم والجداول القديمة عند الحاجة. ملف SQL المرافق يضع أساس Oracle للجداول التالية: الشركات، الفروع، السنوات المالية، المستخدمون، الأدوار، الصلاحيات، نطاق المستخدم، سجل الدخول، وإعدادات التاريخ المحاسبي.

## البيانات المطلوبة لإكمال التحويل

لتحويل النظام كاملًا بدقة، نحتاج أيضًا إلى ملفات `.fmb` أو `.fmx` لبقية الشاشات، أو مخطط قاعدة البيانات وملفات DDL/Export للجداول والحزم، وخاصة حزم المستخدمين والصلاحيات والإعدادات العامة. ملف `ERP_LOGIN.frm` وحده يكفي لتصميم شاشة الدخول وسياق الجلسة، لكنه لا يكفي لإعادة بناء المبيعات والمخزون والتقارير والقيود بالكامل.
