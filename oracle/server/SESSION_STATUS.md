# حالة خادم Oracle لهذه الجلسة

تم تشغيل Oracle XE 21c داخل حاوية Docker باسم `onyx-oracle` على شبكة المضيف لهذه الجلسة. استخدمت شبكة المضيف لأن بيئة العمل لا توفر جداول iptables اللازمة لشبكة Docker الافتراضية.

| العنصر | الحالة |
|---|---|
| Oracle Image | `gvenzl/oracle-xe:21-slim` |
| الحاوية | `onyx-oracle` |
| PDB | `XEPDB1` — `READ WRITE` |
| Listener | TCP `1521` — جاهز |
| Schema التطبيق | `ONYX_APP` — اتصال ناجح، 0 جدول قبل الاستيراد |
| Schema المرحلي | `ONYX_LEGACY_STAGE` — اتصال ناجح، 0 جدول قبل الاستيراد |
| التخزين | Docker volume باسم `onyx_oracle_data` |
| بيانات الاستيراد | المسار `/home/ubuntu/mido/oracle/server/imports` داخل البيئة الحالية |

تم إنشاء كلمات مرور عشوائية محلياً داخل `.env`، وهو ملف مستبعد من Git. لم يتم تضمين أي كلمة مرور في المستودع أو التقارير.

## ملاحظات تشغيلية

الحاوية تعمل داخل بيئة العمل الحالية وقد تتوقف عند انتهاء الجلسة أو سبات البيئة. هذا الخادم مناسب للتحليل والاستيراد المرحلي والاختبارات، وليس خادماً إنتاجياً دائماً. لم يتم استيراد Data Pump بعد؛ الخطوة الآمنة التالية هي نسخ ملف الـ dump إلى مجلد `imports`، استخراج DDL باستخدام `impdp ... sqlfile`، مراجعته، ثم تنفيذ الاستيراد إلى `ONYX_LEGACY_STAGE` فقط.

حدثت مشكلة توافق مع `docker-compose` القديم الموجود في Ubuntu، لذلك تم تشغيل الحاوية بأوامر Docker مباشرة مع الحفاظ على نفس إعدادات `docker-compose.yml`.
