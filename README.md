# أونكس المحاسبي

نظام محاسبي مكتبي عربي يعمل على Windows 10/11 باستخدام Electron ويدعم واجهة RTL، مع مسارين للتشغيل: اتصال مباشر بقاعدة Oracle عند توفرها، ووضع تجريبي محلي للتجربة الفورية دون Oracle.

## التشغيل السريع على Windows

بعد فك حزمة التطبيق شغّل `أونكس المحاسبي.exe`. إذا لم يجد التطبيق إعدادات Oracle أو تعذر الاتصال، ينتقل تلقائيًا إلى الوضع التجريبي المحلي. بيانات الدخول التجريبية هي:

| الحقل | القيمة |
|---|---|
| اسم المستخدم | `admin` |
| كلمة المرور | `demo123` |

في الوضع التجريبي يمكن اختبار لوحة التحكم والقيود ودليل الحسابات والمبيعات والمشتريات والمخزون والعملاء والموردين وإدارة المستخدمين، وتُحفظ البيانات محليًا داخل التخزين المحلي للتطبيق.

## التطوير المحلي

```bash
npm install
npm start
```

لإنشاء نسخة Windows غير مثبتة لاختبارها داخل بيئة البناء:

```bash
npm run build:win -- --dir
```

ولإنشاء مثبت Windows بصيغة NSIS:

```bash
npm run build:win
```

ستظهر مخرجات البناء داخل `dist`، وتوجد النسخة غير المثبتة داخل `dist/win-unpacked`.

## الاتصال بقاعدة Oracle

يُفضّل وضع بيانات الاتصال خارج Git في متغيرات البيئة التالية قبل تشغيل التطبيق:

```powershell
$env:ONYX_DB_USER = "ONYX_APP"
$env:ONYX_DB_PASSWORD = "ضع_كلمة_المرور"
$env:ONYX_DB_CONNECT_STRING = "192.168.1.10:1521/ORCL"
npm start
```

يمكن استخدام ملف إعداد Windows مستقل لتعيين هذه المتغيرات ثم تشغيل التطبيق، مع تعديل عنوان الخادم واسم الخدمة وفق بيئة العميل. لا تُضمّن كلمة المرور داخل المستودع أو داخل ملف التوزيع.

قبل استخدام العمليات الحقيقية على Oracle، نفّذ مخطط الأساس ثم ترحيل الصلاحيات:

```text
oracle/001_security_and_fiscal_schema.sql
oracle/migrations/006_security_roles_permissions.sql
```

ترحيل الصلاحيات يضيف صلاحيات الوحدات والأدوار `ADMIN` و`ACCOUNTANT` و`VIEWER` التي تعتمد عليها الواجهة وطبقة Electron.

## الوحدات المنفذة

| الوحدة | الوظائف الحالية |
|---|---|
| لوحة التحكم | مؤشرات المبيعات والأرباح والمصروفات والسيولة مع حالة مصدر البيانات |
| القيود اليومية | إنشاء قيد متوازن، عرض السجلات، والبحث |
| دليل الحسابات | إضافة الحسابات وعرضها والبحث فيها |
| المبيعات والمشتريات | إنشاء مستندات تجريبية مع حساب الإجمالي وتحديث كمية الصنف |
| المخزون | إضافة الأصناف والأسعار والكميات وحد إعادة الطلب لاحقًا |
| العملاء والموردون | إضافة الجهات والبحث فيها |
| المستخدمون والصلاحيات | إنشاء مستخدمين تجريبيين، أو إدارة مستخدمي Oracle وأدوارهم |
| Oracle | قراءة البيانات الحديثة والقديمة، وإنشاء الحسابات والجهات والأصناف والقيود والفواتير عبر طبقة آمنة في العملية الرئيسية |

## ملاحظات التشغيل

الوضع التجريبي مخصص للعرض والاختبار وليس بديلًا عن Oracle في بيئة الإنتاج. عند توفر Oracle، تعرض الواجهة حالة الاتصال وتستخدم عمليات قاعدة البيانات الفعلية. الجلسة المحلية لا تخزّن كلمة المرور، بينما تستخدم طبقة Oracle تجزئة PBKDF2 وقفلًا مؤقتًا بعد محاولات الدخول الفاشلة.

## بنية المشروع

| الملف | الغرض |
|---|---|
| `index.html` | هيكل واجهة RTL وشاشة الدخول والوحدات |
| `styles.css` | التصميم المرئي المتجاوب |
| `renderer.js` | حالة الواجهة والوضع التجريبي وعمليات CRUD |
| `preload.js` | جسر IPC الآمن بين الواجهة والعملية الرئيسية |
| `main.js` | نوافذ Electron ومعالجات الصلاحيات والجلسة |
| `db.js` | طبقة Oracle والاستعلامات والمعاملات |
| `oracle/` | مخططات Oracle والتحليلات والترحيلات |

## حالة الإصدار

هذه نسخة MVP قابلة للتجربة والبناء على Windows. قبل الإصدار التجاري النهائي ينبغي إضافة النسخ الاحتياطي والاستعادة، التقارير المحاسبية النهائية، إعداد الشركة والفرع والسنة المالية، إدارة الضرائب، الاختبارات على مخطط Oracle الفعلي، وتوقيع مثبت Windows بشهادة ناشر.
