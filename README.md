# أونكس المحاسبي

نظام محاسبي مكتبي عربي يعمل على Windows 10/11 باستخدام Electron ويدعم واجهة RTL، مع مسارين للتشغيل: قاعدة Access محلية بصيغة MDB للاختبار الحي، أو اتصال مباشر بقاعدة Oracle عند ضبط `ONYX_DB_ENGINE=oracle`.

## التشغيل السريع على Windows

بعد فك حزمة التطبيق شغّل `أونكس المحاسبي.exe`. ينشئ التطبيق في أول تشغيل ملف MDB تلقائيًا داخل `%APPDATA%\\Onyx Accounting\\onyx-local.mdb`. يحتاج إنشاء الملف إلى تعريف **Microsoft Access Database Engine / Access ODBC Driver** على Windows. بيانات الدخول الأولية هي:

| الحقل | القيمة |
|---|---|
| اسم المستخدم | `admin` |
| كلمة المرور | `demo123` |

يمكن اختبار لوحة التحكم والقيود ودليل الحسابات والفواتير والمخزون والعملاء والموردين وإدارة المستخدمين، وتُحفظ البيانات فعليًا داخل ملف MDB المحلي. هذه نسخة اختبار محلية وليست بديلاً عن خادم متعدد المستخدمين.

## التطوير المحلي

للدليل الكامل على تطوير المشروع وبنائه على Windows راجع [WINDOWS_DEVELOPMENT_AR.md](WINDOWS_DEVELOPMENT_AR.md).

```bash
npm ci
npm start
```

لفحص بيئة Windows قبل تشغيل التطبيق:

```powershell
npm run doctor:win
```

نفّذ الاختبار المرحلي بالترتيب التالي: `npm run doctor:win`، ثم `npm test`، ثم `npm run dev`. بعد ذلك اختبر شاشة التأسيس الأولى، إنشاء ملف MDB، تسجيل الدخول، ثم تبويبات لوحة التحكم والقيود ودليل الحسابات والمبيعات والمخزون.

لتشغيل نسخة MDB محلية بمسار محدد على Windows:

```powershell
$env:ONYX_DB_ENGINE = "access"
$env:ONYX_DB_PATH = "C:\\MidoData\\onyx-local.mdb"
npm start
```

لإنشاء نسخة Windows غير مثبتة لاختبارها داخل بيئة البناء:

```bash
npm run build:win -- --dir
```

ولإنشاء مثبت Windows بصيغة NSIS:

```bash
npm run build:win
```

ستظهر مخرجات البناء داخل `dist`، وتوجد النسخة غير المثبتة داخل `dist/win-unpacked`.

## الاتصال بقاعدة Oracle (اختياري)

يُفضّل وضع بيانات الاتصال خارج Git في متغيرات البيئة التالية قبل تشغيل التطبيق:

```powershell
$env:ONYX_DB_USER = "ONYX_APP"
$env:ONYX_DB_PASSWORD = "ضع_كلمة_المرور"
$env:ONYX_DB_CONNECT_STRING = "192.168.1.10:1521/ORCL"
$env:ONYX_DB_ENGINE = "oracle"
npm start
```

يمكن استخدام ملف إعداد Windows مستقل لتعيين هذه المتغيرات ثم تشغيل التطبيق، مع تعديل عنوان الخادم واسم الخدمة وفق بيئة العميل. لا تُضمّن كلمة المرور داخل المستودع أو داخل ملف التوزيع.

قبل استخدام العمليات الحقيقية على Oracle، نفّذ مخطط الأساس ثم ترحيل الصلاحيات:

```text
oracle/001_security_and_fiscal_schema.sql
oracle/migrations/006_security_roles_permissions.sql
```

ترحيل الصلاحيات يضيف صلاحيات الوحدات والأدوار `ADMIN` و`ACCOUNTANT` و`VIEWER` التي تعتمد عليها الواجهة وطبقة Electron.

## الوحدات المنفذة

| الوحدة | الوظائف الحالية |
|---|---|
| لوحة التحكم | مؤشرات المبيعات والأرباح والمصروفات والسيولة مع حالة مصدر البيانات |
| القيود اليومية | إنشاء قيد متوازن، عرض السجلات، والبحث |
| دليل الحسابات | إضافة الحسابات وعرضها والبحث فيها |
| المبيعات والمشتريات | إنشاء مستندات تجريبية مع حساب الإجمالي وتحديث كمية الصنف |
| المخزون | إضافة الأصناف والأسعار والكميات وحد إعادة الطلب لاحقًا |
| العملاء والموردون | إضافة الجهات والبحث فيها |
| المستخدمون والصلاحيات | إنشاء مستخدمين محليين في MDB أو إدارة مستخدمي Oracle وأدوارهم |
| Access MDB | قاعدة محلية حية تنشأ تلقائيًا للاختبار على Windows |
| Oracle | قراءة البيانات الحديثة والقديمة، وإنشاء الحسابات والجهات والأصناف والقيود والفواتير عبر طبقة آمنة في العملية الرئيسية |

## ملاحظات التشغيل

قاعدة MDB المحلية مخصصة للاختبار على جهاز واحد، وليست بديلًا عن Oracle أو قاعدة متعددة المستخدمين في الإنتاج. عند ضبط `ONYX_DB_ENGINE=oracle` تستخدم الواجهة Oracle. كلمات المرور المحلية تُخزّن بتجزئة PBKDF2 داخل قاعدة البيانات.

## بنية المشروع

| الملف | الغرض |
|---|---|
| `index.html` | هيكل واجهة RTL وشاشة الدخول والوحدات |
| `styles.css` | التصميم المرئي المتجاوب |
| `renderer.js` | حالة الواجهة والوضع التجريبي وعمليات CRUD |
| `preload.js` | جسر IPC الآمن بين الواجهة والعملية الرئيسية |
| `main.js` | نوافذ Electron ومعالجات الصلاحيات والجلسة |
| `db.js` | طبقة Oracle والاستعلامات والمعاملات |
| `access-db.js` | طبقة Access MDB المحلية ومسار CRUD الحي |
| `create-mdb.ps1` | إنشاء ملف MDB تلقائيًا في أول تشغيل Windows |
| `oracle/` | مخططات Oracle والتحليلات والترحيلات |

## حالة الإصدار

هذه نسخة MVP قابلة للتجربة والبناء على Windows، وقد أضيفت إليها نواة محاسبية مركزية للتحقق من توازن القيود ومسار الإقفال والعملات. قبل الإصدار التجاري النهائي ينبغي إضافة النسخ الاحتياطي والاستعادة، ربط الفواتير بالقيود والمخزون، إدارة الضرائب، الاختبارات على مخطط Oracle الفعلي، وسير الموافقات وتوقيع مثبت Windows بشهادة ناشر. راجع `ACCOUNTING_CORE.md` و`oracle/migrations/008_accounting_posting_core.sql` قبل تفعيل بيئة إنتاج.
